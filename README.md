# PowerSource Workbench

PowerSource Workbench is the group-wide desktop workspace. The first release contains the desktop, local search, settings, and invitation-only account access without CRM modules or the previous permission model.

## Repository layout

- `desktop/`: Electron, React, Tailwind CSS, local search, settings, and direct Supabase access.
- `supabase/`: Database migration and Edge Functions for invitation-only Supabase Auth accounts.
- `scripts/`: Ignored environment generation and the one-time administrator bootstrap.
- `web/`: Reserved for a future web client.

## Authentication

There is no public registration, social login, magic link, or one-time-password login. Users see only a username and password. Internally, the desktop maps the username to an account-only email identity and signs in directly through Supabase Auth.

The system administrator creates one-time invitations through an authenticated Supabase Edge Function. Activation is handled by a publishable-key Edge Function that validates the invitation before its privileged client creates the Auth user. The desktop contains only the public Supabase URL and publishable key; secret and legacy service-role keys never enter the Electron build.

## Setup

1. Apply `supabase/migrations/20260903113749_direct_supabase_auth.sql` to the target Supabase database.
2. Deploy `create-work-invitation` and `activate-work-invitation` from `supabase/functions/`.
3. Run `python scripts/configure-local-env.py` to create `desktop/.env` and `supabase/.env`. Use `--replace` only for files previously generated by this script.
4. Run `python scripts/bootstrap-admin.py` once after the migration is active.
5. Run `npm install` and `npm run dev` from `desktop/`.

The ignored root `.env.vps` supplies the `.work` deployment domain. The configurator transfers the existing public and server Supabase keys without printing their values and preserves an already-generated administrator password during migration from the removed Go API.

## Deployment requirement

The public Supabase endpoint must accept the configured publishable key and expose Auth, Data API, and Functions routes. Apply the migration and deploy both functions before distributing the desktop installer. Public registration must remain disabled; invitation activation uses the Auth Admin API only inside the Edge Function.
