# PowerSource Workbench

PowerSource Workbench is the group-wide desktop workspace. The first release contains the desktop, local search, settings, and invitation-only account access without CRM modules or the previous permission model.

## Repository layout

- `desktop/`: Electron, React, Tailwind CSS, local search, settings, and direct Supabase Data API access.
- `backend/`: Go login API (`workbench-api`). Password grants and invitation creation stay here.
- `supabase/`: Database migrations for Workbench profiles and invitations.
- `scripts/`: Ignored environment generation and the one-time administrator bootstrap.
- `web/`: Reserved for a future web client.

## Authentication

There is no public registration, social login, magic link, or one-time-password login. The desktop posts username and password to the Go API. Go maps the unique super administrator to the existing GeoCRM Auth user (`contact` / the GeoCRM password) and returns GoTrue tokens. Workspace rows are then read and written from the desktop against the Supabase Data API with that user JWT, the same split GeoCRM uses.

Invitation creation also goes through Go. The desktop never receives a secret or service-role key.

## Setup

1. Apply `supabase/migrations/20260903113749_direct_supabase_auth.sql` to the target Supabase database.
2. Run `python scripts/configure-local-env.py` to create `desktop/.env`, `backend/.env`, and `supabase/.env`. Use `--replace` only for files previously generated by this script.
3. Run `python scripts/bootstrap-admin.py` once after the migration is active.
4. Run `go run ./cmd/workbench-api` from `backend/`.
5. Run `npm install` and `npm run dev` from `desktop/`.

The ignored root `.env.vps` supplies the `.work` product domain. The configurator copies the existing GeoCRM public Supabase URL and keys. It does not generate a second administrator password.

## Deployment requirement

The public Supabase endpoint must accept the configured publishable key and expose Auth and Data API routes. Public registration must remain disabled. Deploy `workbench-api` before distributing a packaged desktop build that points at `https://api.{domain}`.
