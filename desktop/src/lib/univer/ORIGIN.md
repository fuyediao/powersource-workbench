# Univer OSS data model (in-tree, trimmed)

This directory is a trimmed, in-repo copy of [dream-num/univer](https://github.com/dream-num/univer)
(the open-source Univer core SDK), fused into GeoCRM Electron the same way Aura lives under
[`../mdcore/`](../mdcore/) — first-party `src/lib` source, not an npm install and not a side
`vendor/` tree.

- **Upstream**: <https://github.com/dream-num/univer>
- **Version**: `v0.25.1`
- **License**: Apache License 2.0 — upstream text:
  <https://github.com/dream-num/univer/blob/v0.25.1/LICENSE>
  (not copied here; source files keep upstream Apache headers)
- **Reason**: Univer OSS ships as npm packages, but docx/xlsx/pptx round-trip is a Univer Pro
  (commercial, server-backed) feature. GeoCRM writes its own OOXML import/export
  (see [`../../office/`](../../office/)) against Univer's OSS data model
  (`IDocumentData`, `IWorkbookData`, `ISlideData`), so the relevant data-model packages live here
  as source (not installed from npm) to keep the whole Office stack in one auditable place and
  allow local patches if needed.
- **Lint**: oxlint's `ignorePatterns` excludes `src/lib/univer/**` in
  [`../../../.oxlintrc.json`](../../../.oxlintrc.json) — upstream is not GeoCRM style. It still
  participates in `tsc --noEmit` and the Vite build.

## Scope (post-OnlyOffice cutover)

GeoCRM's Docs/Sheets/Slides tabs are edited via **OnlyOffice Document Server** (see the
OnlyOffice + Supabase Office plan), not an embedded Univer editor. The interactive Univer editor
host, plugin boot chain, and every UI/rendering-only package (`*-ui`, `design`, `rpc`, `telemetry`,
`thread-comment*`, `drawing*`, `engine-formula`, `network`, and all of `sheets*`) were removed —
only the pure data-model pieces that [`../../office/office-exchange.ts`](../../office/office-exchange.ts)
and its `docx-exchange.ts` / `xlsx-exchange.ts` / `pptx-exchange.ts` / `blank-office-file.ts` /
`product-price-template.ts` / `te-submissions-workbook.ts` siblings need to build and read
`IDocumentData` / `IWorkbookData` / `ISlideData` snapshots stay in-tree.

## Layout

Upstream package names are unchanged (`@univerjs/core` still resolves to `shared/core`, etc.).
Vite resolves `@univerjs/<name>` via `univerPackageRel` in
[`../../../vite.config.ts`](../../../vite.config.ts).

| Folder | Kept packages | Role |
|--------|----------------|------|
| [`docs/docs/`](docs/docs/) | `docs` | Docs data-model plugin (selection/skeleton services used transitively by `@univerjs/slides`) |
| [`powerpoint/slides/`](powerpoint/slides/) | `slides` | Slides data model (`ISlideData`, `DEFAULT_SLIDE`) — the only entry `pptx-exchange.ts` imports |
| [`shared/core/`](shared/core/) | `core` | Cross-surface data model (`IDocumentData`, `IWorkbookData`, locale, sheet/doc snapshot utils) — the entry `docx-exchange.ts` / `xlsx-exchange.ts` / `product-price-template.ts` import |
| [`shared/engine-render/`](shared/engine-render/) | `engine-render` | Canvas layout types pulled in transitively by `@univerjs/slides`'s barrel (text shaping / line-breaking for doc layout) |
| [`shared/protocol/`](shared/protocol/) | `protocol` | RPC/permission protocol types used by `shared/core` |
| [`shared/themes/`](shared/themes/) | `themes` | Theme service used by `shared/core`'s `Univer` class |
| [`types/`](types/) | — | GeoCRM ambient typings (`WorkerGlobalScope`) |

Everything else previously vendored here (`docs-ui`, `docs-drawing*`, `docs-hyper-link*`,
`docs-thread-comment-ui`, all of `excel/` i.e. `sheets*`, `powerpoint/slides-ui`, `shared/ui`,
`shared/design`, `shared/drawing*`, `shared/engine-formula`, `shared/network`, `shared/rpc`,
`shared/telemetry`, `shared/thread-comment*`) had no remaining importer once the Univer editor
host was retired and was deleted. Re-derive the kept/removed split with a reachability trace from
`@univerjs/core` and `@univerjs/slides` (the only two bare `@univerjs/*` specifiers imported
outside this directory) before re-adding any package here.

## What is excluded

- Upstream unit tests (`*.spec.ts`, `__tests__/`) — not needed to parse/serialize OOXML.
- `examples/`, `e2e/`, `storybook/`, the Vue 3 / Web Component UI adapters — never copied.
- All `@univerjs-pro/*` packages and the separate `dream-num/univer-presets` repo — commercial /
  curated-bundle code, not part of this tree.
- Every interactive-editor package listed under "Scope" above — removed once nothing outside
  `src/lib/univer/` imported them (see the reachability note above).
- `@univerjs/icons` stays a normal npm dependency (small, versioned icon component library, not part
  of the `dream-num/univer` monorepo).

## GeoCRM-authored substitutes for upstream build-time files

One file is not part of upstream's committed source — it is generated by upstream's own build
tooling and regenerated here once, since GeoCRM does not run that build:

- `shared/engine-render/components/docs/layout/hyphenation/pattern-loaders.gen.ts` — upstream
  generates this from `./patterns/*.ts` during its own build; GeoCRM's copy uses Vite's
  `import.meta.glob` instead of a hand-written import list.

Also added: `types/worker-global-scope.d.ts`, a minimal ambient declaration for `WorkerGlobalScope`
(from the `WebWorker` lib, which conflicts with the `DOM` lib this project uses) so
`engine-render`'s local-fonts feature-detection type-checks.

## Updating

To pick up a newer OSS tag for the exchange layer, re-run the same sparse copy (source only, tests
excluded) into the matching category folder (`docs/docs/`, `powerpoint/slides/`, or `shared/core/`
+ `shared/engine-render/` + `shared/protocol/` + `shared/themes/`) and refresh the data-model types
consumed by `office-exchange.ts` and its siblings.
